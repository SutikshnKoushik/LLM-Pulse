## Accounts and devices in one dashboard

- Manage multiple ChatGPT/Codex, Claude Code, Kimi Code and GLM/Z.AI connections
  in a compact account manager, alongside supported API reporting connections.
- Pair installations and exchange recorded usage directly between trusted devices.
- View all installations together or select this computer or another installation.
- Compare recorded usage by device, account, provider and model, including model
  breakdowns inside chart tooltips. Copied records count once in the combined view.
- Discover Codex logs written by Multica automatically.
- Keep this computer's current Codex limits visible beside combined histories.

## Codex reset history

Inspect the last 10, 30 or all recorded weekly windows and available reset credits.
Reset timing and cause are shown separately: manual credit redemption, scheduled,
provider-inferred or unknown. A short failed status poll no longer loses evidence
of a non-expired redeemed credit. Confirmed and inferred causes remain distinct;
missing evidence, expired credits, changed accounts and long gaps stay unknown.
The reset history belongs to this installation's recorded account observations;
it is not a synchronized reset ledger for every linked account.

## Faster history views

Completed charts survive restarts and appear with their actual saved timestamp
while fresh usage is collected in the background. Live quotas are read separately;
old allowances are never restored from the chart cache. Device switching cancels
obsolete requests. Large provider histories use one shared aggregation pass, and
stored encrypted histories are verified outside the UI process.

On a development measurement of about 413,000 recorded observations, complete
combined aggregation fell from 8.2 to 3.1 seconds with identical results. A saved
four-installation view returned in 95 ms after restart. These are measured examples,
not a guarantee for every machine. The first import, a newly selected uncached
history and explicit full refreshes still require collection or calculation time.

## What to expect

- Direct sync requires a reachable LAN or existing private network and overlapping
  uptime for new data. It has no dashboard-operated central sync server or relay.
- Sign-in credentials stay on their installation. Pairing shares usage and selected
  account/quota metadata, not provider login credentials.
- Historic account ownership depends on evidence in the logs. Unknown ownership
  and records observed on several installations remain explicit. Recorded tokens
  are not provider billing totals, and account allowance percentages are not additive.
- Kimi Code currently reports account quotas; Moonshot API reports balance.
  Neither provides a complete token history here. Claude Code needs its official
  CLI and a valid local session. Provider API reporting needs the relevant
  provider permissions.
- macOS builds are ad-hoc signed without Apple notarization. Install the DMG
  manually; macOS automatic update delivery is not announced. Windows installers
  are unsigned. Publish only after checking all platform artifacts for the final tag.
